Designing quarterly progress reports that actually align to licensure standards

Duccio Mondanelli · 2026 · ~8 min read

!

Watch your steps! This is a construction zone. This case study is actually a work in progress right now.

Every teacher apprenticeship program has a quarterly progress report. It's rare to find one that actually measures progress. Most of them are generic forms that ask the same questions for every candidate, and none of them can answer the only question the report exists to answer: is this person on track to become the specific kind of teacher we are licensing them to be?

Ours couldn't either, at first. This is the story of how I rebuilt it, and what other programs can borrow from the process.

The classic problem: one generic form for two different licenses

Our program prepares special education teachers in two Minnesota licensure tracks: Academic and Behavioral Strategist (ABS), which is K-12, and Early Childhood Special Education (ECSE), which runs birth to age six. These are almost completely different jobs. An ECSE teacher writes IFSPs, coaches families in natural environments, and works with infants and toddlers, with all the developmental considerations of the case. An ABS teacher runs FBAs and BIPs, designs academic interventions, and manages K-12 IEP and eligibility processes.

Our original progress report we were planning to use treated them almost identically. The content standards section used four vague categories like "foundational knowledge" which, incidentally, mapped to no actual standard in either license. The form never distinguished an IFSP from an IEP! I immediately spotted the alarm bells: as a former Special Educator and mentor, overworked and with little to no time in my day, I would have filled it out because I had to, and the data would have told us almost nothing.

A progress report that isn't accessible to the mentors will not measure progress. It's checking a box, creating the feeling of data collection while providing little actual insight.

The redesign

1. Split the form

The first decision was the hardest to push for: one form for two programs was the foundational problem, and no amount of clever section design would fix it. We built two separate instruments, visually distinct at a glance so nobody ever grabs the wrong one. Colors are used to create clarity, implementing core ideas of intentional design in a space often constrained by academic and insitutional bindings.

The obvious idea

Each program needs its own visual identity and set of tools. One size fits all ends up confusing everyone, starting with the mentors.

2. Map every item to a real standard

Every content item on each form now traces to something a licensing body or the program itself actually requires: Minnesota's PELSB standards for each license, the program's core skills, and High Leverage Practices. If an item couldn't be traced, it got cut. This sounds obvious in retrospect, but it required going line by line through the standards for both licenses and being willing to delete sections people were used to.

One rule from that process worth borrowing: use only the the frameworks your program has actually adopted. Our first redesign draft included a well-regarded national framework that we don't use, because it seemed like it belonged. What it did was create confusion and waste time for everyone.

The obvious idea

Everything tracked must be actual worthwhile data. Stop tracking stuff you don't need "just in case".

3. Build in quarter-based progression

A form that asks the same questions in quarter one and quarter seven is telling candidates that nothing is supposed to change. We wrote explicit expectations by phase, from observation through co-teaching to independent practice, so a "developing" rating in an early quarter reads as normal and the same rating in a late quarter will read as a flag. The forms now carry the program's theory of growth inside it.

The obvious idea

If we ask the same questions in different quarters, we're likely to get the same answers.

4. Design for the mentor's thirty seconds

The person completing this form is a mentor teacher with a full caseload. Every design decision was optimized for their time: dropdown selections instead of free text wherever a rating is structured, visual grouping that matches how an observation actually flows, and nothing that requires them to go look something up. We built the documents programmatically, which meant we could also do things standard templates can't, like styling dropdowns so they're impossible to miss.

The obvious idea

If the busiest person in the loop can't complete the instrument accurately in one sitting, it's the instrument that is wrong.

What I'd tell another program

  • If you serve multiple licensure areas, you need multiple instruments. One size fits all doesn't work and makes everything more confusing.
  • Link every item to a standard or cut it. It's great to be inspired by frameworks, but if your institution isn't using them, it's wasted time for everyone.
  • Embed progression in the tools you use. The form should already show what quarter it is.
  • Optimize for the mentor. If the mentor is overwhelmed, there's no data for us to analyze.
  • Whoever on your team can script document generation is worth their weight in gold. Hand-maintaining multiple documents is how things get lost.
  • Create templates, centralize, set up dashboards.
